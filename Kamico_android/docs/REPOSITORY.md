## 分支与验收流程

2026-10-20 起按根 [AGENTS.md](../../AGENTS.md) 执行。已有提交与版本标签继续保留，不为采用新流程重写历史。

1. 开始新一轮功能改进、版本更新或 bug 修复前，确认工作区状态，从本地 `main` 新建功能分支。版本读取 `main` 中客户端 `pubspec.yaml` 的 `version`，取去掉构建号的语义版本；例如 `1.0.0+27` 对应 `feature+1.0.0`，名称中的 `+` 为实际字符，不使用计划升级后的版本号。
2. 同一轮实现、交付后的修订与重新验证继续使用原分支。新任务遇到同名分支时依次使用 `feature+1.0.0-2`、`feature+1.0.0-3`，保留已有分支与提交。
3. 代码、相关文档和本地提交均留在功能分支；完成验证后交付同版本 Release / Debug，记录具体版本、构建号及产物校验值，等待用户验收。自动检查通过、构建成功或代理自行确认均不能代替用户验收。
4. 用户明确验收本轮最终产物后，核对其对应源码提交，再切回 `main`，以 `git merge --no-ff <功能分支>` 合并并记录交付版本和验收依据。用户的验收即授权执行这次本地合并，无需重复确认；若后续修订或冲突解决改变了交付源码，应重新验证、交付并取得验收后再合并。
5. 分支合并与远程推送分别处理；远程配置、创建和推送仍按用户授权执行。
