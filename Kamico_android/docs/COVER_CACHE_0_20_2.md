# 0.20.2 阅读返回后的封面缓存

## 复现与原因

使用真实 CoverImage、DetailScreen 与离线 ReaderScreen，合成图片与受控 2 MiB 图片缓存上限复现：先缓存首页缩略图和另一作品详情，加载三张阅读页后再返回，两种封面重新下载，请求累计由 2 增至 4。命令：`flutter test --no-pub test/detail_artwork_test.dart --plain-name "reader pages do not evict"`。修复后同一路径请求保持 2 次，红绿过程见 [回归日志](cover-cache-0.20.2-regression.log)。

原因是阅读页大图和封面共用 Flutter 默认 ImageCache 的 LRU，连续阅读会淘汰暂时不可见的封面。该回归保持封面 URL 和解码尺寸不变；未发现阅读返回路径主动清除图片缓存，因此排除换键和主动清理作为该复现的必要原因。

## 修复

- CoverImageProvider 为首页、详情及使用 CoverImage 的界面提供独立封面 LRU。启动时把原有 100 MiB 解码缓存保留预算分为普通／阅读图片 84 MiB、封面 16 MiB；封面最多 96 个解码项，尺寸仍为 64–400px。不是将原缓存额外扩大。
- 内存上限指可复用 LRU，正在显示的图片、编码字节、GPU 表面等另有生命周期，不代表应用总内存限制。真正的系统内存压力会释放封面复用缓存，达到容量或进程重启后仍允许重新加载；不增加持久封面磁盘缓存。
- 图片解析、缓存查询和用户重试统一访问封面池，失败条目会移除，不长期卡在失败的 pending 状态。详情封面和背景仍共用同一个解码帧。

## 详情到期刷新

还复现了另一种等待：元数据缓存超过 5 分钟后被移除，即使图片缓存存在，详情页也先等待 API，造成封面重新加载的观感。

现保留最多 40 部进程内最近详情，到期后先显示上次内容，同时后台请求最新数据；成功后更新页面。刷新失败时保留已有内容，显示简短提示和重试入口。无旧数据的首次加载仍显示正常加载／失败状态。账号或连接配置变化、收藏／购买操作失效及购买前强制价格复核保持，过期数据显示不会跨账号复用。

该路径先在原实现中确认旧标题被隐藏的断言失败，修复后通过；并覆盖刷新失败、再次重试与成功更新，见 [到期刷新回归](detail-refresh-0.20.2-regression.log)。

## 验证

- `flutter analyze --no-pub` 无问题，完整 106 项回归通过，见 [验证日志](verification-0.20.2.log)。包括封面压力复现、LRU 容量与系统内存压力回收、缓存到期后台更新、账号隔离、图片同步和失败重试。
- 小米 22041211AC / Android 14 的独立 Debug 应用，预先进入另一作品详情后，阅读到第 16 页，再返回首页并进入已缓存作品。阅读图片池达到 84,242,880 字节（约 80.3 MiB），封面池始终为 13 项、8,183,880 字节（约 7.8 MiB）。最终返回前后的 13 个封面 ImageStreamCompleter 对象全部复用。见 [匿名 VM 汇总](cover-cache-0.20.2-device.json)。
- 使用 ADB 语义、日志和 VM 数据，无截图、无真实账号写操作。调试期间手机锁屏导致连接中断，用户解锁后重新建立 Debug 会话完成验证。VM 原始对象、封面地址与认证连接信息不归档。
- 真机验证证明本次路径的缓存复用，不将它换算为 Release FPS，也不保证所有封面永久驻留内存。原阅读磁盘缓存、下载文件和项目／全局编译依赖缓存均保留。
