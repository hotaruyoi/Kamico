# 0.19.0 界面与滚动性能

## 界面改动

- 参考图仅用于按钮、圆角和层级的元素设计，保留现有页面结构。发现入口、紧凑章节、注册入口、维护按钮、标签、分段选择及签到选中态统一采用无描边填充；主操作使用主题色，次操作使用柔和表面色。目录工具图标继续保持默认透明，输入框的聚焦和错误提示仍保留。
- 详情操作栏：阅读按钮占可用内容宽度 50%，下载和收藏为图标按钮，各占 15%，保留间距和尾部留白；窄屏下图标触控区至少 48dp。图标仍有工具提示和可访问性名称。
- 有效历史章节显示“继续 第x话”，优先读取章节标题中的话／章／集编号，缺少编号时使用目录顺序；历史章节已移除时恢复“开始阅读”。实际恢复章节与页码沿用原逻辑。
- 收藏面板、下载选章、简介与目录折叠、搜索及阅读导航保持原交互。

## 性能证据

在小米 22041211AC / Android 14 的独立 Debug 应用采集 Dart VM Timeline。场景为已加载的发现页，先两次预热滚动，再八次交替 600px / 800ms 滑动。关闭下载、PDF 生成与账号写操作；手机继续使用用户 VPN。

定位到首页各分组的 `SliverLayoutBuilder` 随滚动约束反复运行，重新创建网格委托和可见卡片。改为外层 `LayoutBuilder` 仅在宽度等布局依赖变化时创建网格，滚动期间复用子树；内容仍由 SliverGrid 懒构建，字体、密度和宽度变化仍响应。

| Debug 事件 p95 | 修复前 | 仅性能修复 | 最终界面 |
| --- | ---: | ---: | ---: |
| Frame | 21.119ms | 3.620ms | 3.367ms |
| LAYOUT (root) | 17.976ms | 1.250ms | 1.217ms |
| GPURasterizer::Draw | 3.375ms | 4.834ms | 4.289ms |

聚合原始结果：[修复前](performance-0.19-baseline.json)、[仅性能修复](performance-0.19-optimized.json)、[最终界面](performance-0.19-final.json)。只保存事件耗时汇总，不保存 VM 认证地址、网络载荷或完整时间线。

这是 Debug/JIT、已缓存内容的一次短时对照，样本数量和滚动可见内容会有差异，不能换算成 Release FPS。栅格耗时略增，不能宣称所有指标均有改善；主要收益是避免滚动中的重复布局和构建。最终 Frame 事件仍有一次超过 16.667ms，未宣称完全消除长帧；未据此推断内存泄漏或内存下降。

回归测试先把滚动范围扩大到实际进入内容区，在原实现中确认“滚动不重建已有卡片”的断言失败，修复后通过；同时确认宽度变化仍重建响应式网格。见 [回归过程](performance-0.19-regression.log)。热重载替换根布局时出现过一次布局断言；完整热重启后重新滚动和进入详情，抽查当前进程日志未再次发现该断言，冷启动结果在交付时另记。
