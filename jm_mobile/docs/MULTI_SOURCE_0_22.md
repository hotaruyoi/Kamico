## 产品行为

- “我的”顶部账号栏右侧为填充式切换按钮，上方图标、下方小字 `JM` / `Pic`；点击直接切换，停留在“我的”。未登录源显示未登录，需要鉴权时提供登录入口。
- 两个账号各自保存安全令牌与资料，密码不落盘。退出、认证过期、修改连接配置只影响对应源；配置的源域名视为可信，凭据不跨源使用。
- 发现、搜索、分类/排行榜、云端收藏和账号跟随全局源。发现及书架分别保留来源页面；滚动键带来源。搜索历史、筛选及最后查询分别保存，重启记住当前源，旧安装默认 JM。
- 本地历史、收藏、下载共用入口，以 **JM / PIC 连续分区**展示，各区内保留原排序；本地收藏文件夹共用，不把两源条目交错排列。
- 从历史、本地收藏或离线库打开另一源作品，详情、阅读、评论、收藏及相邻章节始终绑定作品来源，不改变全局选择。阅读返回作品详情；首页按钮回到当前全局发现页。
- 下载任务绑定创建时的来源，切源不暂停下载。两源共用并发额度及管理页面，暂停/恢复/取消仍按任务处理。继续保持前台下载限制，不新增后台服务。
- 新 PDF 放 `Downloads/kamico/JM/作品_编号/章节_编号.pdf` 或 `PIC/`；Debug 根目录为 `kamico-debug`，自选目录下也分源。旧公共 PDF 不移动，旧离线文件不重新下载、不强制转换。
- Pic 复用发现、分类、排行榜、搜索、详情、阅读、收藏、下载/PDF、评论/回复、资料与签到。按实际能力隐藏 JM 周刊/连载、云端收藏文件夹、云端历史、购买及补签；Pic 邮箱登录，不显示 JM 原站注册链接。
- 聊天室、游戏、广场、独立社区、超分、代理/ECH/DoH 及旧 Qt 数据导入不在本轮范围。

## 实现与兼容

`ComicSource` 为共用漫画流程接口，`JmClient` 与 `PicClient` 分别实现协议；公共 UI 不需要构造另一源的伪造上游 JSON。`Comic` 带 `source` 和实际封面地址，`ReaderChapter` 带来源，Pic 目录由适配器构造共用模型。

根 `AppSession` 持有公共资源，通过 `forSource()` 提供稳定的来源会话，`active` 只用于主页面。详情与阅读在打开时绑定来源，下载通过任务自带来源分发，公共图片下载按 `ReaderChapter.source` 分发；不通过可变的当前 API 调度旧任务。根 session 共用进度写队列，防止两源导航交替保存时覆盖历史。

本地内容身份使用来源加远程 ID：JM 沿用旧键，Pic 为 `pic|id`；向上游请求时仍用原 ID。历史、章节进度、收藏、下载去重与磁盘目录均按此身份区分。旧 JSON / manifest 缺少来源时按 JM 读取；保留旧 token、账号资料、搜索、阅读缓存和下载目录，避免升级后丢失现有数据。新目录导入记录归属导入时的当前源。

Pic 请求采用相对路径（含查询串）+ 秒级时间戳 + nonce + 方法 + API key 的小写 HMAC-SHA256；普通 JSON envelope，无 JM 响应解密。账号 token 只发给该源配置的 API 主机；图片按媒体 URL 请求原始字节，无 JM 分片还原，不发账号 token。POST 超时/连接失败不自动重放，包括只读搜索 POST。日志只记录固定路由族、方法、状态和耗时，不记录密码、token、搜索文本或响应正文。

Pic 目录和章节图片均取齐分页后再返回，缺页或数量变化会失败，不发布不完整离线章。参考代码指出 `ep.order` 可重复，并按升序目录位置请求章节图片；本版章节标识同时保留漫画、位置和 episode ID。此行为已用重复 order 合成目录验证，真实上游仍需连通环境核验。

详情缓存继续采用 5 分钟鲜活期、最多 40 本的进程内 LRU，允许旧内容先显示；账号和连接配置变化使对应缓存失效。JM 原有协议和图片恢复行为保持，原 Qt 项目未修改。Pic 协议来源及原许可文本补入第三方声明、资源和应用许可页。
