# 0.20.1 详情封面与背景同步加载

## 原因与修复

0.20.0 的清晰封面按显示宽度解码（多数手机为 400px），背景通过另一处 Image.network 固定解码到 192px。即使 URL 相同，ResizeImage 的缓存键也不同，会独立加载与解码；封面命中缓存时，背景仍可能等待。背景还在元数据之前独立开始显示，因此两种先后顺序都可能出现。

详情页现由 DetailArtwork 统一解析一个 ImageStream，预先加载一份尺寸受限的图片。清晰封面与模糊背景直接使用同一个 ImageInfo 中的 ui.Image，不再各自创建图片请求。元数据和图片均就绪时，在同一次界面更新中显示两处图像；失败时共用一处重试，重试后也同步恢复。退出详情时解除监听并释放自持有的帧句柄。

保留原图片缓存，不新增磁盘缓存或依赖；图片解码尺寸继续根据清晰封面的物理宽度取整，上限 400px。按宽度展示背景、顶部对齐、sigma 18、高斯模糊与渐变层均保持。首页封面等其他缩略图仍沿用原有尺寸策略。

## 可复现回归

命令：`flutter test --no-pub test/detail_artwork_test.dart`。

使用真实 DetailScreen 与合成 HTTP 图片流，预先缓存清晰封面后阻塞后续图片响应。原实现中封面已显示、背景 RawImage.image 仍为 null，断言失败；修复后两者同帧显示，整个场景只出现一次图片请求。红绿过程见 [回归记录](artwork-0.20.1-regression.log)。过程中一次测试框架环境变量未及时复位的问题也已修正，不作为产品缺陷结论。

新增三类回归：

- 图片先于元数据到达时，不让背景单独先出现；数据就绪后两处图像对象相同。
- 图片失败后，只需一次重试，即可恢复清晰封面和背景。
- 已缓存封面进入详情，不再为模糊背景发起额外请求，且两处 ui.Image 引用相同。

完整静态检查无问题，103 项测试通过，见 [验证日志](verification-0.20.1.log)。不以“无异常”替代加载同步断言。

## 真机 Debug

小米 22041211AC / Android 14，继续使用用户 VPN。通过 ADB 进入详情，并读取 Debug VM 的 RawImage 对象；清晰封面（cover）和模糊背景（fitWidth）的 image 指向同一对象身份，见 [匿名汇总](artwork-0.20.1-device.json)。VM 临时引用编号可能不同，比较使用对象 identityHashCode，并核对两个 fit 枚举，而非直接比较临时引用字符串。

当前进程有限日志未匹配到相关未处理异常或布局断言。本轮没有截图，没有真实账号写操作；VM 认证地址和对象原始数据不归档，临时配置在验证后移除。这些结论针对加载链路，不推断所有设备的网络速度或 Release FPS。
